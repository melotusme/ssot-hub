# 易用性重构规划（2026-11-05）

> 进度：A 已完成；B 已完成（班课保留为独立类型，扫描软件需"关注"才进主列表）；C 进行中。

目标：把"按类型逐字段登记"改成"说一句话或贴一张图就记下来"。本文规划三件事：字段分层和默认值、AI 做主入口、合并类型。标【待定】的需要你确认。

## 1. 为什么现在做、按什么顺序做

现状：19 种类型、253 个字段，登记一项平均面对 13 个输入框；一件事（比如"电脑给孩子用了"）要拆成好几条记录。

**你本机正在用的台账是空的**（旧库里只有 1 条测试设备）。这意味着现在改数据模型几乎没有迁移成本；等录进几百条后再改，就要写迁移、逐条核对。因此顺序调整为：

| 阶段 | 内容 | 依赖 |
| --- | --- | --- |
| A | 字段分层 + 默认值 + 系统字段自动填 | 无，可以马上做 |
| B | 合并类型 + 关系模型（快照 v4） | 用 A 的分层标记 |
| C | AI 主入口 + AI 修改已有记录 | 建在 B 的新模型上，避免做两遍 |

A 先做，是因为它小、马上见效，并且 B、C 都要用到它给字段打的"核心 / 更多 / 系统"标记。B 放在 C 前面，是因为 AI 能做的"交接、续费、退役"这类操作要针对新模型写；先做 C 再改模型，就得写两遍。

## 2. 完成标准

用下面这些真实场景验收，每个都应该在 **一次输入 + 一次确认** 内完成：

1. "新买了 iPad Air 给孩子上网课用，2999 元" → 一台设备，所有者是自己，使用人是孩子。
2. 贴一张 iCloud+ 扣费截图 → 一条订阅：月付 21 元，付费账号是 Apple ID。
3. "MacBook-A 以后给老婆用，我换 M4 了" → 一次交接：旧使用记录结束，新记录开始，历史保留。
4. "Claude 会员不续了" → 订阅标为不续费或退役，不需要打开表单。
5. "家里路由器下有哪些设备" → 路由器清单导入后只问需要你确认的那几项。
6. 手动登记一台设备：默认只显示不超过 5 个输入框。

另外：首次使用不需要先理解"设备 / 系统环境 / 软件安装"的区别。

## 3. 阶段 A：字段分层 + 默认值

**schema 里给每个字段加 `tier`：**

- `core`：表单默认显示，每种类型 3 到 5 个；
- `more`：收在"更多信息"里，展开才显示；
- `system`：资料依据、证据、观测时间，由系统自动填，表单不显示（详情页只读显示）。

**默认值（定义在 schema 里，后端生效）：**

| 字段 | 默认 |
| --- | --- |
| 所有者 / 付费成员 | 成员中标为"自己"的那一位 |
| 开始日期、购买日期 | 今天 |
| 币种 | CNY |
| 汇率 / 本币 / 汇率日期 | 币种是 CNY 时不需要填，也不显示 |
| 使用角色 | 主力 |
| 资料依据 | 手动登记为"人工确认"；AI 为"用户描述"；扫描为"机器观测" |

**其他：**

- 列表和详情只突出核心字段；空的"更多"字段在详情里折叠起来。
- 表单底部的"资料依据"等 5 个记账字段只保留"备注"一个。

工作量：小，约半天。不改数据结构，现有快照照常能读。

## 4. 阶段 B：合并类型 + 关系模型（快照 v4）

### 4.1 类型从 19 个合并为 10 个，侧栏分 6 组【待定】

| 侧栏分组 | 新类型 | 合并了原来的 | 核心字段（tier=core） |
| --- | --- | --- | --- |
| 设备 | 设备 | 设备、硬盘与存储（硬盘、U 盘、硬盘盒作为设备种类） | 名称、种类、型号、所有者、所在地 |
| 系统与软件 | 系统 | 系统环境 | 名称、所在设备、系统、类型（实体 / 虚拟机 / 容器） |
| | 软件 | 软件安装（只放你关心的软件，扫描结果另放） | 名称、所在系统、来源、配置来源 |
| 账号 | 账号 | 身份账号、手机号码（号码作为账号种类） | 名称、服务商、登录标识、归属成员 |
| 订阅与服务 | 订阅 | 订阅与许可、eSIM 套餐（作为"通信套餐"类别） | 名称、价格、周期、到期日、付费账号 |
| | 在线服务 | 域名、服务器 / VPS、个人 Agent、网络与穿透 | 名称、种类、服务商、续费订阅 |
| 家人 | 成员 | 家庭成员与组织 | 名称、类型（自己 / 家人 / 孩子 / 组织） |
| | 班课 | 孩子的班课 | 名称、孩子、机构、剩余课时、到期日 |
| 其他 | 资源 | 资源目录 | 名称、类别、平台 |
| | 配置来源 | 配置来源 | 名称、权威类型、权威位置 |

原来的字段都保留，只是大多变成 `more`，不会丢信息。

### 4.2 三种"记录型"类型改成关系

| 原类型 | 改成 | 在界面上 |
| --- | --- | --- |
| 使用与交接 | `uses` 关系（成员 → 设备 / 服务，带角色和起止日期） | 详情页"给谁用"按钮；交接是"换人"按钮 |
| 资源副本与位置 | `stored_on` 关系（资源 → 设备 / 账号，带路径、用途、核实状态） | 资源详情页"存放位置"列表 |
| 节点接入 | `joins` 关系（设备 / 系统 → 网络，带地址、连通性） | 网络详情页"节点"列表 |

**关系统一模型：** `{id, type, from, to, attrs, valid_from?, valid_to?}`。

- `type` 是封闭枚举，由 schema 定义每种关系允许的两端类型和属性；
- 现在的字段引用（`device_id`、`owner_id` 等）继续当字段用，不强制迁成关系，避免一次改太多；
- 自由文本关系 `links` 迁到 `related`（一般关联）类型，原文字放进 `note` 属性。

### 4.3 扫描结果不进主列表

Homebrew、Git、Mac / PVE 盘点脚本扫出来的软件（你的私有盘点里有 2000 多条）放进单独的"扫描清单"，按系统查看。只有你点"关注"的才变成正式的软件记录。这样软件列表不会被淹没。

### 4.4 迁移

- 快照 v3 → v4 的迁移在 Rust 里做一次，读到旧快照时自动转换，旧文件不改；附测试覆盖每个旧类型。
- `private/` 下的盘点 JSON 用同一个迁移函数转换。
- 同步：v4 快照不能被旧版客户端读取；升级前所有设备先同步到同一个版本。

工作量：中等，约 2 到 3 天。

## 5. 阶段 C：AI 做主入口

### 5.1 首页一个输入框

- 总览页顶部放一个大输入框："说一句，或贴一张截图 / 拖入文件"。
- 不需要先选类型；"手动登记"降为输入框旁的次要按钮。
- 也支持直接粘贴剪贴板里的截图。

### 5.2 AI 不只新建，也能改

AI 返回的是"操作"，不只是"新记录"：

| 操作 | 例子 | 确认界面 |
| --- | --- | --- |
| 新建 | 新买的 iPad | 卡片，只显示核心字段，可展开 |
| 修改 | "iCloud 涨价到 25 了" | 改前 / 改后对比 |
| 交接 | "MacBook-A 给老婆用了" | 旧使用人 → 新使用人，从哪天开始 |
| 退役 | "Claude 会员不续了" | 将退役的记录 |
| 关联 | "这个 Google 账号登录在 iPad 上" | 两端和关系类型 |

所有操作一起预览、一次确认，在一个事务里写入；任何一条校验不过就全部不写，并告诉你是哪一条、什么原因。

### 5.3 问而不是填

缺必填信息时，AI 用一句话追问（"这台 iPad 是谁在用？"），给出可点的选项（已有成员），而不是打开表单。

### 5.4 隐私

- 保持现在的规则：只发送你给的材料，以及已有资产的 id、类型、名称；修改已有记录时，额外发送该记录的核心字段。
- 设置里显示当前服务和模型；可以把某些服务标为"不用于家庭资料"【待定：是否要这个开关】。

工作量：中等，约 2 到 3 天。

## 6. 不在这次范围

- 自动后台扫描、定时提醒；
- 手机端；
- 多设备同时编辑和自动合并；
- 语音输入（以后可加，接口和文字输入一样）。

## 7. 需要你确认的事

2. 班课是否保留成独立类型？还是先放进"其他"？
